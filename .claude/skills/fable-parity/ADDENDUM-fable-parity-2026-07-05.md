## 追記：オーケストレーションで Opus を「上位モデル」級にできるか、正直に測ってみた

> 本編（歩行進化・LLM マージ・性格ダイヤル）とは別テーマですが、同じ「手元の計算資源で LLM に何をさせられるか」の一環として、もう一本の実験記録を短く追記します。

上位モデル（Opus より 1 段上のティア）がもうすぐ使えなくなるので、
「並列に何度も考えさせて敵対的に検証する足場（オーケストレーション）」で、
手元の Opus をそのモデル級に引き上げられないか——を実装して、**独立の判定者で盛らずに測った**。
結論だけ先に：**一律には届かない。でも一番の収穫は別のところにあった。**

### 3 つの軸で結論が正反対になった

- **客観的に正解が決まる推論**（総当りでキーを計算したパズル・数え上げ・状態機械）:
  **Opus は既に天井**。上位モデルとの差はゼロ（難易度を上げて 2 度測り 18/18）。
  足場は無力どころか、1 問で `{"answer":"test"}` という**中身が空の合成を出荷して自爆**した
  （＝素の Opus が解ける問題に"失敗する余地"を足していた。検証済みの最良試行へ戻すガードで修正）。

- **オープンな品質**（設計・仕様・分析。正解キーが無いので非 Anthropic の Codex に匿名 blind ランク）:
  初めて構造が出た。**素の Opus 単発は 15 タスク中ほぼ一度も 1 位にならない**（＝単発品質の差は実在）。
  ただし **上位モデルは設計で強く分析で弱く、足場は分析で勝ち設計で退行**する。**タスク依存**で、一律 parity は言えない。

- **検証の相関盲点**：ここが本命。**同じモデルに自分の宿題を採点させると同じ盲点を共有**する。
  検証だけ別系列（Codex）に出したら、**Opus の検証者が「確認済み」とした前提を、Codex が具体根拠で覆した**：
  > あるライブラリについて Opus は「429 応答を customize できる API がある」と確認済みにした。
  > Codex は「その最新版に該当 API も retry metadata も存在しない」と反証 → 前提は「不確実」に格下げ →
  > 計画に「着手前に実ソースを読んで食い違いを解消せよ」という検証ステップが自動で入った。

  Opus 一色のパイプラインなら、自信のある誤りをそのまま出荷していた。

### 持ち帰り（実務の地図）

| 状況 | 使うもの |
|---|---|
| 客観的に正解が決まる推論 | **何も足すな**（天井。足場は自爆リスク） |
| 微妙な技術点を詰める分析・デバッグ | **足場**（検証が生成より安く、勝てる） |
| 広く一貫した設計 | **素の 1 パス**（統合が一貫性を壊す） |
| 前提の誤りが高コストな計画・移行 | **別系列で検証**（相関盲点を潰す） |

### 正直な但し書き

数値は小 N・単一 blind 判定の指標値。judge を 3 回シャッフルで回すと **5 タスク中 2 つしか勝者が安定しなかった**
（測定自体が思ったより noisy）。ただし「素の Opus はほぼ一度も best にならない（1/15）」は固い。
**「一律 parity 達成」という美味しい主張は、正直に測ったら成立しなかった**——研究の価値は勝った気になることでなく、
内訳を正直に開示すること、という回でした。
