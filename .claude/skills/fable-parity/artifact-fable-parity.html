オーケストレーションで Opus は「上位モデル」級になるか

上位モデルがもうすぐ使えなくなる。並列に何度も考えて検証する足場で、手元の Opus を引き上げられないか——を、盛らずに独立の判定者で測った記録。

結論：タスク次第。一律には届かない。 そして一番効いたのは品質の底上げではなく、別系列モデルによる検証だった。「一律 parity 達成」という美味しい主張は、正直に測ったら成立しなかった。

10 / 15
上位モデルが素の Opus に勝った数（10 タスク追試を含む）。ただし Opus は証明・数値で勝ち返す。

足場が上位モデルを上回った数。ただし設計 q1 では素の Opus すら下回り最下位。

上位モデルは 設計・仕様で強く、分析・デバッグで最下位。足場は検証が有利な分析タスクで勝ち、一貫性重視の設計タスクで退行する。統合・接ぎ木の段が、単一の深い 1 パスの一貫性を壊すためだ。足場はタダではなく、一様に良くもない。

隠さない 2 つの事実

研究の価値は勝った気になることでなく、内訳を正直に開示すること。

▲ 足場の自爆

統合が空のプレースホルダを出荷した

難タスク群で足場が 1 問だけ落とした。中身は統合エージェントが {answer:"test"} という、スキーマは満たすが中身が空のプレースホルダ。オーケストレーションが、素の Opus が解けるタスクに"失敗する余地"を足していた。隠さず、統合結果が異常に短ければ検証済みの最良試行へフォールバックするガードを追加した。

● 別系列が突いた盲点

Opus の「確認済み」を Codex が反証した

計画検証で、ある前提を Opus の検証者は「確認済み」と判定した。ところが別系列の Codex が具体的根拠で反証：「そのライブラリの最新版は別実装に移行しており、その API は存在しない」。

前提は「不確実」に格下げされ、「着手前にコードを読んで食い違いを解消せよ」という検証ステップが計画に自動で織り込まれた。同じモデルに自分の宿題を採点させない——これが実測で唯一はっきり価値の出た改善だった。

再利用できる方法論

結論そのものより、測り方のほうが資産として残った。

  • キーは計算で作る。客観タスクの正解を手で書くと著者の間違いがベンチを汚す。総当り／厳密計算で保証する。
  • 判定者は独立系列で、blind に。自己採点は禁物。非 Anthropic の Codex に匿名ランクさせ、決定的シャッフルで位置バイアスを消す。
  • perishable ファースト。再生成できないのは上位モデルの出力だけ。安く大量に凍結し（1 エージェント／タスク・品質 15 本を保存）、Opus 側と判定は後からでよい。
  • 異常に良い結果は内訳を疑う。「一律 parity 達成」は美味しいが、測っていないことは主張しない。残ったのは「タスク依存」という地味だが正しい地図。

数値はすべて小 N・単一 blind 判定の指標値であり、統計的に検出力のあるベンチマークではありません。「測った範囲でこう出た」以上のことは主張しません。上位モデルアクセスが消える前に凍結した出力群を基準に、今後より大きな N で追試できるようにしてあります。
