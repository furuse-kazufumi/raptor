# q14 — fable-raw (archetype: data-structure)

## Task

Design a data structure supporting insert(x), remove(x), and getRandom() each in O(1) average time, with getRandom uniform over current elements. Specify the two backing structures (dynamic array + hash map of value->index), the exact remove algorithm (swap-with-last then pop, and fixing the moved element's index), and the SUBTLE bug when the element being removed IS the last element (or the only element). Handle duplicates: state what changes if duplicate values must be supported.

## Fable answer

# RandomizedSet: O(1) insert / remove / getRandom

## 1. Backing structures

```
arr : dynamic array (vector) of values     — dense, arr[0..n-1] are exactly the current elements
idx : hash map value -> position in arr    — idx[v] = i  <=>  arr[i] == v
```

Invariants (must hold after every operation):
- `len(arr) == len(idx)`
- for every `v` in `idx`: `arr[idx[v]] == v`
- `arr` has no holes — this density is what makes `getRandom` uniform.

Values must be hashable. All O(1) bounds are *average* (hashing) and *amortized* (array append/pop with doubling; if you also shrink, shrink at 1/4 occupancy to half capacity, never at 1/2, or amortization breaks).

## 2. Operations

**insert(x)** — set semantics:
```
if x in idx: return false
arr.append(x)
idx[x] = len(arr) - 1
return true
```

**getRandom()** — precondition: nonempty (define behavior explicitly: error/exception on empty; `rand(0..-1)` is undefined):
```
return arr[uniform_int(0, len(arr)-1)]
```
Uniform because `arr` is dense: every element occupies exactly one of `n` equally likely slots. O(1) worst case.

**remove(x)** — swap-with-last then pop:
```
if x not in idx: return false
i    = idx[x]              # position of the victim
j    = len(arr) - 1        # position of the last element
last = arr[j]

arr[i]    = last           # (a) move last element into the hole
idx[last] = i              # (b) fix the moved element's map entry
arr.pop()                  # (c) shrink array by one
del idx[x]                 # (d) delete victim's map entry — MUST BE LAST (see §3)
return true
```
No O(n) shifting occurs because we fill the hole with the *last* element, not by sliding.

## 3. The subtle bug: x IS the last element (or the only element)

When `i == j` (`x == last`), steps (a)–(d) alias the same key: `idx[last]` **is** `idx[x]`.

- **Safe order (above):** (a) is a no-op self-assign; (b) rewrites `idx[x] = i` harmlessly; (c) pops it; (d) deletes `idx[x]`. Correct — because the map **delete happens after** the map update.
- **Buggy order** (very common):
  ```
  del idx[x]        # delete first...
  arr[i] = last
  idx[last] = i     # ...then this RESURRECTS x with index i == new length (stale!)
  arr.pop()
  ```
  Consequences of the stale entry `idx[x] = i` (i is now out of bounds, or later occupied by a different value):
  - `contains(x)`/`insert(x)` wrongly report x present; `insert(x)` is refused forever.
  - `len(idx) != len(arr)` — invariant broken.
  - A later `remove(x)` reads the stale index and either indexes out of bounds or **removes a different, innocent element** — silent data corruption.
  - The *only-element* case (`n == 1`, so `i == j == 0`) triggers the identical bug and additionally leaves `idx` nonempty while `arr` is empty; a subsequent `getRandom` on a "nonempty" structure (judged by map size) crashes.

Two equivalent fixes — pick one and be consistent:
1. **Ordering fix:** always update `idx[last]` *before* deleting `idx[x]` (the code in §2), i.e., delete the victim's key last.
2. **Guard fix:** `if i != j: { arr[i] = last; idx[last] = i }` then `arr.pop(); del idx[x]`. This also skips the redundant self-assign.

Also note a second micro-trap: read `last = arr[j]` **before** any writes; reading it after `arr[i] = last`-style reordering in a refactor is a classic source of the same aliasing bug.

## 4. Duplicates (multiset, LeetCode 381 variant)

Change the map to `pos : value -> hash-set of indices` (must be a hash set, not a sorted structure, to keep O(1)):

```
insert(x):
    absent = (x not in pos) or pos[x] is empty
    arr.append(x)
    pos[x].add(len(arr)-1)
    return absent                      # "was it new?" — always inserts

remove(x):
    if x not in pos or pos[x] empty: return false
    i = pos[x].pop_any()               # remove ONE arbitrary index of x
    j = len(arr) - 1
    last = arr[j]
    if i != j:                         # guard is now MANDATORY, not stylistic
        arr[i] = last
        pos[last].remove(j)            # remove old index of moved element...
        pos[last].add(i)               # ...add new one (this exact pair-order)
    arr.pop()
    if pos[x] empty: del pos[x]        # avoid unbounded empty-set garbage
    return true

getRandom(): unchanged — arr[uniform(0, n-1)]
```

New subtleties introduced by duplicates:
- **`x == last` by value, different indices** (e.g., x at {2,5}, j=5): if `pop_any` returned i=2, then `last == x` and `pos[last]` is the *same set* we just popped from; the `remove(j); add(i)` pair still works because j(=5) is genuinely in the set and i(=2) is genuinely its new home. If `pop_any` returned i=5(=j), the guard skips the swap entirely. Without the `i != j` guard, the single-occurrence case does `pos[last].remove(j)` on an index already popped (error) and `pos[last].add(i)` resurrects a stale index — same corruption family as §3.
- The set update must be `remove(j)` then `add(i)` on `pos[last]`; doing `add(i)` first is harmless *except* when i==j (add then remove annihilates a valid entry) — the guard sidesteps this too.
- **Uniformity semantics:** sampling `arr` is uniform over *stored copies*, so a value's probability is proportional to its multiplicity. That is the standard contract. If you instead need uniform over *distinct* values, this structure does not give it; you'd maintain a second (array + map) over distinct keys and sample that.
- `insert` is now always successful; its boolean means "value was not present before," matching the multiset API.

## 5. Complexity summary

| op | array + map (set) | array + map-of-sets (multiset) |
|---|---|---|
| insert | O(1) amortized avg | O(1) amortized avg |
| remove | O(1) avg | O(1) avg |
| getRandom | O(1) worst | O(1) worst |
| space | O(n) | O(n + distinct values) |

Worst case degrades to O(n) only via adversarial hash collisions (mitigate with randomized/seeded hashing); array append/pop are amortized via doubling (and 1/4-shrink rule if shrinking).
