# q11 — fable-raw (archetype: proof-reasoning)

## Task

Prove the correctness of the sort-then-two-pointer algorithm for 3SUM (find all unique triples summing to 0). State the loop invariant for the inner two-pointer scan, prove it never MISSES a valid pair for the fixed first element, prove it enumerates each triple at most once (the deduplication argument), and state the exact complexity with justification. Be rigorous about why moving the pointers is safe.

## Fable answer

# Correctness of Sort-Then-Two-Pointer 3SUM

## 0. Algorithm (fixed for reference)

Input: array of n integers. Output: all *distinct value triples* (x, y, z), x ≤ y ≤ z, x + y + z = 0, realizable by three distinct indices.

```
sort A ascending                            # A[0] ≤ A[1] ≤ … ≤ A[n−1]
for i = 0 .. n−3:
    if i > 0 and A[i] == A[i−1]: continue   # (S1) skip duplicate first elements
    T = −A[i];  l = i+1;  r = n−1
    while l < r:
        s = A[l] + A[r]
        if s < T:  l += 1
        elif s > T: r −= 1
        else:
            output (A[i], A[l], A[r])
            while l < r and A[l+1] == A[l]: l += 1   # (S2) skip dup second elements
            while l < r and A[r−1] == A[r]: r −= 1   # (S3) skip dup third elements
            l += 1;  r −= 1
```

Note (S1) compares with the *previous* index (process the **first** occurrence). Comparing with the next index instead is a classic bug: on `[−1, −1, 2]` it would skip i = 0 and miss (−1, −1, 2).

---

## 1. Loop invariant for the inner scan

Fix a processed outer index i and let T = −A[i]. Call an index pair (p, q) a **target pair** if i < p < q ≤ n−1 and A[p] + A[q] = T.

> **INV:** At the start of every iteration of the `while l < r` loop:
> for every target pair (p, q), if p < l **or** q > r, then the *value pair* (A[p], A[q]) has already been output during this inner scan.

Equivalently: every target value pair not yet output still has a witness (p, q) entirely inside the window [l, r].

**Initialization.** l = i+1, r = n−1, so every target pair satisfies l ≤ p < q ≤ r; the hypothesis "p < l or q > r" is vacuously false. INV holds.

**Maintenance — case s < T (we execute l ← l+1). This is the pointer-safety argument.**
We must show any target pair newly excluded, i.e., with p = l, is already output. Suppose A[l] + A[q] = T for some q > l.
- If q ≤ r: since A is sorted, A[q] ≤ A[r], hence A[l] + A[q] ≤ A[l] + A[r] = s < T — contradiction. So no target pair with p = l has its partner inside the window. **This is exactly why discarding l is safe: A[r] is the largest value l can be paired with in the window, and even that is too small.**
- If q > r: by INV (old window), the value pair (A[l], A[q]) was already output.
Either way the newly excluded pairs are covered; INV is preserved.

**Maintenance — case s > T (r ← r−1).** Symmetric: for any q = r and p < r inside the window, A[p] + A[r] ≥ A[l] + A[r] = s > T, so no in-window target pair uses r; pairs with p < l are covered by old INV.

**Maintenance — case s = T (output + skips (S2)(S3) + l++, r−−).**
The pair (A[l], A[r]) =: (a, b) is output now. Let l′, r′ be the new pointers. Newly excluded indices on the left are exactly those p ∈ [l, l′−1], and by construction of (S2) all satisfy A[p] = a; a target pair (p, q) then forces A[q] = T − a = b, so its value pair is (a, b) — just output. Symmetrically, newly excluded q ∈ [r′+1, r] have A[q] = b, forcing value pair (a, b). Pairs excluded earlier are covered by old INV. INV is preserved.

**Termination.** Every branch strictly decreases r − l (by ≥ 1), so the loop terminates after ≤ n − i − 2 iterations, ending with l ≥ r.

---

## 2. No valid pair is missed (completeness for fixed i)

At termination l ≥ r, so no pair (p, q) can satisfy l ≤ p < q ≤ r (that would need l < r). Hence **every** target pair satisfies p < l or q > r, and by INV its value pair has been output. Therefore:

> **Lemma 1 (inner completeness).** For each processed i, every distinct value pair (y, z) with y + z = −A[i], realizable by indices i < p < q, is output exactly by the scan at i.

**Completeness of the whole algorithm.** Let (x, y, z), x ≤ y ≤ z, x + y + z = 0 be realizable by distinct indices a < b < c; since A is sorted and x ≤ y ≤ z, we may take (A[a], A[b], A[c]) = (x, y, z). Let i\* = min{ j : A[j] = x }. Then i\* ≤ a; replacing a by i\* still gives valid distinct indices i\* < b < c (b > a ≥ i\*). The outer loop *processes* i\* : it is the first occurrence of x, so either i\* = 0 or A[i\*−1] < A[i\*], and (S1) does not skip it. By Lemma 1 applied at i\* with target pair (b, c), the triple (x, y, z) is output. ∎

Edge cases: n < 3 → outer loop empty, and no triple exists — vacuously correct. All-equal arrays, all-zero arrays, no-solution arrays are all covered by the above (the invariant never assumed distinct values).

---

## 3. Each triple is output at most once (deduplication)

Every output triple has the form (A[i], A[l], A[r]) with i < l < r, hence A[i] ≤ A[l] ≤ A[r]: outputs are in **canonical nondecreasing form**, and the first component is the minimum of the triple.

**(a) Within one inner scan.** Claim: successively output pairs have strictly increasing second component. When (a, b) is output at (l, r), step (S2) moves l to the last index of the contiguous block of value a (sortedness ⇒ equal values are contiguous), then l += 1 puts l strictly past that block; l is nondecreasing thereafter, so every later A[l] > a. Hence any later output pair (a′, b′) has a′ > a, so (a′, b′) ≠ (a, b). All pairs output in one scan are pairwise distinct, so all triples output for a fixed i are pairwise distinct. (Symmetrically A[r] is strictly decreasing across outputs, which also shows the two skip loops can never re-land on the same pair.)

**(b) Across different outer indices.** Suppose the same triple were output at processed indices i₁ < i₂. Then A[i₁] = A[i₂] (both equal the triple's minimum, per the canonical-form remark; note a triple can only ever be emitted at a scan whose fixed value is its minimum, since A[i] ≤ A[l] ≤ A[r]). By sortedness, A[i₁] = A[i₂] with i₁ < i₂ forces A[i₂] = A[i₂−1], so (S1) skips i₂ — contradiction. So each distinct minimum value is scanned at exactly one outer index, and combined with (a), **each distinct triple is output exactly once** (at least once by §2, at most once here). ∎

---

## 4. Complexity

- **Sort:** O(n log n) (comparison sort).
- **Outer loop:** ≤ n iterations.
- **Inner scan for each i:** define potential Φ = r − l ≤ n − i − 2 initially. Every iteration of the while loop — including each step of the skip loops (S2)/(S3) — decreases Φ by at least 1, and Φ ≥ 0. Hence total pointer movements per scan ≤ n, each O(1) work, so each inner scan is O(n), including all deduplication skips (amortized against Φ).
- **Total:** O(n log n + n²) = **O(n²) time**. This is also Θ(n²) in the worst case for this algorithm: e.g., an array of n distinct positive integers runs the full inner scan (≈ n − i steps) for every i, giving Σᵢ (n − i) = Θ(n²), independent of output size.
- **Output cost:** the number of distinct zero-sum triples is at most the number of (i, pair) outputs, each charged O(1) inside the same Θ(n²) budget (each output coincides with a Φ-decreasing step).
- **Space:** O(1) auxiliary beyond the sort's O(log n)–O(n) and the output itself.

Practical caveat: with fixed-width integers, compute A[l] + A[r] against T = −A[i] (as written) or use a wider type; a + b + c can overflow even when each element fits.
