# q7 — fable-raw (archetype: adversarial-spec)

## Task

Write a RIGOROUS TOTAL specification for compare(a, b) comparing two Semantic Versioning 2.0.0 strings, returning -1/0/1. Define the exact grammar, then specify precedence for: major/minor/patch numerically; pre-release vs release (pre-release is LOWER); dotted pre-release identifier comparison (numeric identifiers compared numerically, alphanumeric lexically, numeric < alphanumeric, a larger set of fields wins when all preceding equal); and that BUILD METADATA is ignored for precedence. Enumerate adversarial inputs (leading zeros in numeric identifiers, empty identifiers, huge numbers, unicode, missing patch, 'v' prefix) and define accept/error for each. Argue totality.

## Fable answer

# SPECIFICATION: `compare(a, b)` for Semantic Versioning 2.0.0

## 0. Signature and domain

```
compare : String × String → {-1, 0, +1}        (partial on all strings)
```

Totalized form (the normative one):

```
compare : String × String → {-1, 0, +1} ⊎ {ERROR(reason)}
```

- Inputs are sequences of Unicode code points (or bytes; §1 restricts the accepted set to printable ASCII, so byte/code-point views coincide on the valid domain).
- `compare` first runs `parse` on each argument. If either fails, the result is `ERROR` (fail-closed: never guess, never coerce). Otherwise it returns exactly one of -1, 0, +1 per §3.
- Non-string arguments (null, undefined, numbers, objects) are outside the domain → `ERROR(type)`. No implicit `toString`.
- No preprocessing of any kind: no trimming, no case folding, no Unicode normalization (NFC/NFD/NFKC), no `v`-stripping, no locale-sensitive operations. Comparison of characters, where required, is by ASCII code-point value only.

---

## 1. Grammar (exact, normative)

A string is a **valid semver** iff it matches `<valid semver>` in this BNF, anchored at both ends (the *entire* string, no leading/trailing characters, including whitespace or BOM):

```
<valid semver>        ::= <version core>
                        | <version core> "-" <pre-release>
                        | <version core> "+" <build>
                        | <version core> "-" <pre-release> "+" <build>

<version core>        ::= <major> "." <minor> "." <patch>
<major>               ::= <numeric identifier>
<minor>               ::= <numeric identifier>
<patch>               ::= <numeric identifier>

<pre-release>         ::= <dot-separated pre-release identifiers>
<dot-separated pre-release identifiers> ::=
                          <pre-release identifier>
                        | <pre-release identifier> "." <dot-separated pre-release identifiers>

<build>               ::= <dot-separated build identifiers>
<dot-separated build identifiers> ::=
                          <build identifier>
                        | <build identifier> "." <dot-separated build identifiers>

<pre-release identifier> ::= <alphanumeric identifier> | <numeric identifier>
<build identifier>       ::= <alphanumeric identifier> | <digits>

<alphanumeric identifier> ::= <non-digit>
                            | <non-digit> <identifier characters>
                            | <identifier characters> <non-digit>
                            | <identifier characters> <non-digit> <identifier characters>
<numeric identifier>  ::= "0" | <positive digit> | <positive digit> <digits>
<identifier characters> ::= <identifier character> | <identifier character> <identifier characters>
<identifier character>   ::= <digit> | <non-digit>
<non-digit>           ::= <letter> | "-"
<digits>              ::= <digit> | <digit> <digits>
<digit>               ::= "0" | <positive digit>
<positive digit>      ::= "1" … "9"
<letter>              ::= "A"…"Z" | "a"…"z"        (ASCII only, U+0041–U+005A, U+0061–U+007A)
```

Equivalent anchored regular expression (the grammar is regular; groups: major, minor, patch, prerelease, build):

```
^(0|[1-9]\d*)\.(0|[1-9]\d*)\.(0|[1-9]\d*)
 (?:-((?:0|[1-9]\d*|\d*[A-Za-z-][0-9A-Za-z-]*)
      (?:\.(?:0|[1-9]\d*|\d*[A-Za-z-][0-9A-Za-z-]*))*))?
 (?:\+([0-9A-Za-z-]+(?:\.[0-9A-Za-z-]+)*))?$
```

Consequences to note explicitly (these are where implementations go wrong):

- G1. `major`/`minor`/`patch` are **mandatory** decimal integers with **no leading zeros** (`0` itself is legal; `00`, `01` are not). Exactly three; `1.2` and `1.2.3.4` are invalid.
- G2. A **numeric** pre-release identifier (all digits) MUST NOT have leading zeros. An **alphanumeric** identifier (contains ≥1 of `[A-Za-z-]`) MAY start with zeros: `01a`, `0-0`, `-`, `--` are valid alphanumeric identifiers.
- G3. Build identifiers are `[0-9A-Za-z-]+` with **no** leading-zero restriction: `+001`, `+0.0` are valid.
- G4. Identifiers are non-empty; therefore `1.0.0-`, `1.0.0+`, `1.0.0-a..b`, `1.0.0-.a`, `1.0.0-a.`, `1.0.0+a..b` are all invalid.
- G5. The only structural separators are the first `-` after `patch` (starts pre-release), `.` (within core / within identifier lists), and the first `+` (starts build). Hyphens *inside* identifiers are ordinary characters: `1.0.0-a-b+c-d` is valid. A second `+` anywhere is invalid.
- G6. Alphabet is exactly the 63 ASCII characters `[0-9A-Za-z-]` plus separators `.` `+` and the pre-release-introducing `-`. Every other code point (space, `_`, `α`, fullwidth digits `1`, zero-width joiners, combining marks, BOM) → invalid.

Parsed value:

```
V = (M : ℕ, m : ℕ, p : ℕ,
     pre : list of Id,            -- possibly empty list = "is a release"
     build : ignored)
Id = Num(n : ℕ)                   -- identifier that is all digits, value as unbounded integer
   | Alnum(s : ASCII string)      -- identifier containing ≥1 non-digit, kept verbatim
```

`M, m, p, n` are **mathematical integers (arbitrary precision)**. The grammar imposes no magnitude bound; see §4.5.

---

## 2. Precedence — identifier comparison primitive

Define `cmpId : Id × Id → {-1,0,1}`:

1. `cmpId(Num(x), Num(y))` = sign of `x − y` (exact integer arithmetic, never floating point, never fixed width).
2. `cmpId(Alnum(s), Alnum(t))` = lexicographic comparison of `s`, `t` as sequences of ASCII code points: compare code points left to right; at the first index where they differ, the smaller code point makes the smaller identifier; if one is a proper prefix of the other, the **shorter is smaller**. Note ASCII order implies `'-'(45) < '0'..'9'(48–57) < 'A'..'Z'(65–90) < 'a'..'z'(97–122)`; comparison is case-sensitive (`ALPHA < alpha`, since `A` < `a`).
3. `cmpId(Num(_), Alnum(_)) = -1` and `cmpId(Alnum(_), Num(_)) = +1` — **numeric identifiers always have lower precedence than alphanumeric identifiers**, regardless of content (`Num(999999) < Alnum("-")`).

Classification is decided by the grammar, not by content heuristics: `"1"` → `Num(1)`; `"1a"`, `"a1"`, `"-1"`, `"01a"` → `Alnum`. (`"01"` never reaches `cmpId`; it is a parse error, §1 G2.)

`cmpId` is a total order on `Id` (trichotomous, transitive): case 1 inherits from ℤ, case 2 is the standard lexicographic order on finite ASCII strings (a total order), case 3 places all `Num` strictly below all `Alnum`; the union of two total orders layered disjointly is a total order.

## 3. Precedence — `compare(a, b)`

Given parses `A = (M_a, m_a, p_a, pre_a, _)` and `B = (M_b, m_b, p_b, pre_b, _)`:

**Step 1 — core, numeric, lexicographically by position.**
If `M_a ≠ M_b` return `sign(M_a − M_b)`.
Else if `m_a ≠ m_b` return `sign(m_a − m_b)`.
Else if `p_a ≠ p_b` return `sign(p_a − p_b)`.

**Step 2 — release vs pre-release.** (cores equal)
If `pre_a = []` and `pre_b = []` return `0`.
If `pre_a ≠ []` and `pre_b = []` return `-1` (a pre-release has **lower** precedence than the corresponding release: `1.0.0-rc.1 < 1.0.0`).
If `pre_a = []` and `pre_b ≠ []` return `+1`.

**Step 3 — dotted pre-release lists.** (both non-empty)
For `i = 1 .. min(|pre_a|, |pre_b|)`:
  `c := cmpId(pre_a[i], pre_b[i])`; if `c ≠ 0` return `c`.
All shared positions equal → return `sign(|pre_a| − |pre_b|)`: **the larger set of fields has higher precedence** (`1.0.0-alpha < 1.0.0-alpha.1`). Note this rule applies *only* among two pre-releases; it never overrides Step 2 (a longer pre-release list is still `< ` the release).

**Step 4 — build metadata.**
There is no step 4. `build` was discarded at parse time and MUST NOT influence the result in any code path: `compare("1.0.0+sha.abc", "1.0.0+sha.def") = 0`, `compare("1.0.0", "1.0.0+x") = 0`, `compare("1.0.0-a+huge.build", "1.0.0-a") = 0`. Consequently `compare(a,b)=0` does **not** imply `a = b` as strings; it means *equal precedence*. `compare` induces a total order on the quotient of valid semvers by the relation "equal after deleting build metadata" (on which it *is* antisymmetric), and a total preorder on valid semver strings.

Normative chain (must hold, from SemVer §11):
`1.0.0-alpha < 1.0.0-alpha.1 < 1.0.0-alpha.beta < 1.0.0-beta < 1.0.0-beta.2 < 1.0.0-beta.11 < 1.0.0-rc.1 < 1.0.0` — note `beta.2 < beta.11` (numeric, not lexical) and `alpha.1 < alpha.beta` (numeric < alphanumeric).

## 5. Totality argument

Claim: for every pair `(a, b)` of strings, `compare(a,b)` yields exactly one element of `{-1, 0, +1, ERROR}` in finite time; restricted to `Valid × Valid` it yields exactly one of `{-1,0,+1}` and is a total preorder.

1. **Parsing is a total, decidable function.** The grammar of §1 is regular (witness: the anchored regex). Membership of a finite string in a regular language is decidable in `O(|s|)`; the match either succeeds (yielding a unique parse — the grammar is unambiguous: separators `.`/first-`-`/first-`+` deterministically delimit fields, and Num/Alnum classification of each identifier is determined by "contains a non-digit", a decidable predicate) or fails. So each input maps to exactly one of {a parse, ERROR}.
2. **Every code path returns.** If either parse fails → ERROR (single exit). Otherwise Steps 1–3 execute: Step 1 performs ≤3 integer comparisons (integer comparison is total and terminating even at arbitrary precision, since the operands are finite digit strings); Step 2 is a 4-way case split on emptiness, exhaustive by construction (`pre` is a list, either empty or not — no third state); Step 3 loops at most `min(|pre_a|,|pre_b|)` times, a finite bound, each iteration calling `cmpId`, itself total (§2: 3-case split exhaustive over `Id×Id`; each case terminates). The final tie-break `sign(|pre_a|−|pre_b|)` is total. Hence exactly one of -1/0/+1 is produced.
3. **Trichotomy.** By construction the algorithm is a lexicographic composition of the total orders/comparators ⟨ℕ, ℕ, ℕ, releaseFlag(release=1 > pre=0), lex(cmpId) with shortlex tie-break⟩; a lexicographic product of total preorders is a total preorder, so for all valid `a,b` exactly one of `a<b`, `a≈b`, `a>b` holds — never "incomparable".
4. **Coherence properties** (on valid inputs): reflexivity `compare(a,a)=0` (all fields equal at every step); anti-commutativity `compare(a,b) = −compare(b,a)` (every primitive comparator used is anti-commutative and the step sequence is symmetric); transitivity of `≤` (lexicographic composition preserves transitivity of the component orders: ℤ-order, list-shortlex over the total order `cmpId`). Antisymmetry holds only modulo build metadata (§3 Step 4) — this is by design of SemVer §10 and is not a totality defect: totality requires an answer for every pair, not string-level antisymmetry.
5. **No hidden partiality.** The three classic escape hatches are closed: (i) overflow — excluded by mandating unbounded integers or an explicit ERROR profile (§4.5), never undefined behavior; (ii) encoding — excluded because the valid alphabet is 7-bit ASCII, so UTF-8/UTF-16/code-point disagreements cannot arise inside the valid domain, and anything outside it errors at parse; (iii) recursion depth — the algorithm is iterative with bounds `3 + min(|pre_a|,|pre_b|)` comparisons, each `O(len)`; overall `O(|a|+|b|)` time (times big-int comparison cost, itself linear in digit count).

∎ `compare` is total on String×String (with ERROR as the explicit, fail-closed image of the invalid region) and a terminating, trichotomous total preorder on valid SemVer 2.0.0 strings, agreeing with SemVer §11 precedence and ignoring build metadata per SemVer §10.
