# q2 — fable-raw (archetype: adversarial-spec)

## Task

Write a RIGOROUS, TOTAL specification for a function parse_iso8601_duration(s) that parses an ISO-8601 duration string (e.g. 'P3Y6M4DT12H30M5S', 'PT0S', 'P1W') into a normalized structure. Define the exact accepted grammar (including the week form and the fact that the time designator T is required iff any time component is present), then enumerate EVERY adversarial / edge-case input class and specify the precise behavior (accept-with-value or a defined error) for each — including: empty, missing P, T with no time parts, out-of-order components, fractional seconds vs fractional other fields, negative/signed values, overflow-scale values, mixed week-and-other, lowercase designators, and unicode digits. Argue the spec is TOTAL (every input maps to a defined outcome).

## Fable answer

# Specification: `parse_iso8601_duration(s)`

**Version 1.0 — normative unless marked *(informative)*.**
Profile: strict ISO 8601-1:2019 §5.5.2 duration (designator format), with every profile decision the standard leaves open fixed explicitly below. This spec is **total**: §11 proves every possible input maps to exactly one defined outcome.

---

## 1. Scope and non-goals

`parse_iso8601_duration(s)` maps an input value `s` to either a **`Duration` record** or exactly one **defined error**. It is a pure function: no I/O, no locale, no clock, no randomness; identical input always yields the identical outcome.

**Out of scope (all rejected by the grammar, each hitting a *defined* error — see §8):**

- ISO 8601-2 signed/negative durations (`-P1D`, `+P1D`) — rejected, `ERR_SIGN`.
- The alternative representation `P0003-06-04T12:30:05` (ISO 8601-1 §5.5.2.4) — rejected (`ERR_SIGN` at the first `-`; message explains).
- Intervals and repeats (`2026-01-01/P1Y`, `R5/P1D`) — rejected (`ERR_MISSING_P` or `ERR_UNEXPECTED_CHAR`).
- Unit conversion/normalization across units (months→days, `PT24H`→`P1D`, `P1W`→`P7D`): **never performed** (calendar-dependent; `P1M` and `P30D` are distinct values of this function).
- Conversion to total seconds, comparison, arithmetic.

---

## 2. Input domain

The ambient input universe is **all values** the host language can pass.

- **D1.** If `s` is not a Unicode string (sequence of Unicode code points) — e.g. `None`, `bytes`, `int`, `float`, list — outcome is `ERR_TYPE` (Python binding: raise `TypeError`). Byte strings are *not* decoded; decoding is the caller's contract.
- **D2.** Otherwise `s` is a finite sequence of code points `s[0..n-1]`, `n ≥ 0`. Lone surrogates, NUL, controls, any code point whatsoever are in-domain and handled by the character-class partition in §7.
- **D3.** **No Unicode normalization** (no NFC/NFKC, no case folding) is applied. Comparison is raw code-point equality. Consequences: fullwidth `Ｐ` (U+FF30), Cyrillic `Р` (U+0420), fullwidth digits `３` are *not* `P`/digits and are rejected.
- **D4.** Length cap: `MAX_LEN = 4096` code points. If `n > MAX_LEN`: `ERR_TOO_LONG`. (Bounds memory/CPU for adversarial inputs while permitting exact big-number semantics, §6.)

---

## 3. Result type

```
Duration := {
  years   : Q≥0,   months  : Q≥0,   weeks : Q≥0,   days : Q≥0,
  hours   : Q≥0,   minutes : Q≥0,   seconds : Q≥0,
  form    : "week" | "components"
}
```

`Q≥0` = **exact** non-negative rational whose denominator is a power of 10 (i.e., an exact decimal). Binding recommendation: `fractions.Fraction`, `decimal.Decimal` (exact), or `(int numerator, int pow10)`. **Binary floats are forbidden as the stored representation**: `parse("PT0.1S").seconds` must equal exactly 1/10.

**Invariants (guaranteed on every accepted parse):**

- **I1.** `form == "week"` ⟹ all fields except `weeks` are 0. `form == "components"` ⟹ `weeks == 0`.
- **I2.** At most one field has a non-integral *lexical source*, and if so it is the lowest-order (last) component present in the input (§5, F-rules).
- **I3.** All fields ≥ 0 (no signs exist in the grammar).
- **I4.** Absent components are exactly 0. Lexical details (leading zeros `P01D`, trailing fraction zeros `P1.0D`, `,` vs `.`) are **not** preserved; only the numeric value is. Field magnitudes are bounded by `MAX_LEN` (≤ 10^4094).
- **I5.** Two accepted parses are equal iff field-wise numerically equal and `form` equal.

Note: `"P0D"`, `"PT0S"`, `"P0W"` all accept and yield all-zero fields (differing only in `form` for the last). The zero duration is representable; bare `"P"` is not it (rejected, §5 C1).

---

## 4. Error model

Abstract outcome: `Ok(Duration) | Err(code, pos, message)`.

- `pos` = 0-based code-point index of the first offending position; `pos = n` (one past end) for end-of-input errors; `pos = None` for `ERR_TYPE`/`ERR_TOO_LONG`/`ERR_EMPTY`.
- Python binding: return `Duration` on success; raise `DurationParseError(code, pos, message)` (subclass of `ValueError`) for all errors except non-string input, which raises `TypeError`. Raising vs. returning `Err` is a binding detail; the *outcome set* is identical.
- **Determinism rule:** the outcome is defined by the single left-to-right pass of §7. The **first** failing position determines the error; there is no backtracking, so exactly one code applies to any input.

**Error codes (closed set, 15):**

| Code | Meaning |
|---|---|
| `ERR_TYPE` | input is not a Unicode string |
| `ERR_EMPTY` | empty string `""` |
| `ERR_TOO_LONG` | length > `MAX_LEN` |
| `ERR_MISSING_P` | first code point is not `P` (U+0050) and not a sign |
| `ERR_SIGN` | `+` (U+002B), `-` (U+002D), or `−` (U+2212) encountered anywhere |
| `ERR_UNEXPECTED_CHAR` | code point not valid at this position (whitespace, lowercase at start of a component, Unicode digits, `/`, NUL, homoglyphs, …) |
| `ERR_MISSING_DIGITS` | designator with no preceding number (`PD`, `P1DD`) |
| `ERR_MISSING_DESIGNATOR` | number not followed by a valid designator (`P1`, `PT5`, `PT1e5S`, `P1y`) |
| `ERR_MISPLACED_DESIGNATOR` | time designator before `T` (`P1H`, `P1S`) or date/week designator after `T` (`PT1D`, `PT1Y`, `PT1W`) |
| `ERR_ORDER` | designator repeated or out of order within its section (`P1M1Y`, `PT1S1M`, `P1Y2Y`) |
| `ERR_WEEK_MIXED` | `W` combined with any other component (`P1W2D`, `P1Y1W`, `P1WT1H`, `P1W1W`) |
| `ERR_TIME_EMPTY` | `T` present but no time component follows (`PT`, `P1DT`) |
| `ERR_EMPTY_SPEC` | `P` with zero components (`"P"`) |
| `ERR_FRACTION_MALFORMED` | separator without digits on both sides (`PT.5S`, `PT5.S`, `PT1.2.3S`, `PT1.,5S`) |
| `ERR_FRACTION_NOT_LAST` | a fractional number is followed by any further component or `T` (`P0.5Y1M`, `PT1.5H30M`, `P0.5YT1H`) |

## 5. Accepted grammar (normative)

Terminals are exact code points: `P`=U+0050, `T`=U+0054, `Y M D W H S` = U+0059/4D/44/57/48/53, digits = U+0030–U+0039 **only**, decimal marks `.`=U+002E and `,`=U+002C (both accepted, per ISO which prefers comma but permits dot).

ABNF (RFC 5234), fully expanded so that "at least one component" is structural:

```abnf
duration   = %x50 ( week-form / general-form )        ; "P"

week-form  = number %x57                              ; nW  — nothing before or after

general-form = date-part [ time-part ]                ; but not both absent:
             ;   general-form = date-part time-part
             ;                / date-part
             ;                / time-part
date-part  = y-comp [mo-comp] [d-comp]
           / mo-comp [d-comp]
           / d-comp
time-part  = %x54 t-comps                             ; "T"
t-comps    = h-comp [mi-comp] [s-comp]
           / mi-comp [s-comp]
           / s-comp

y-comp  = number %x59        mo-comp = number %x4D
d-comp  = number %x44        h-comp  = number %x48
mi-comp = number %x4D        s-comp  = number %x53
number  = 1*DIGIT [ dec-mark 1*DIGIT ]
dec-mark = %x2E / %x2C
DIGIT   = %x30-39
```

**Side conditions (context-sensitive, normative):**

- **C1 (non-empty):** at least one component overall — structurally enforced above; bare `P` and bare `PT` are underivable.
- **C2 (T iff time):** `T` appears **iff** ≥1 time component is present, and time components appear **only** after `T`. Structurally enforced: `t-comps` is non-empty; `H`/`S` don't occur in `date-part`; the `M` before `T` is months, after `T` is minutes (the grammar disambiguates the overloaded `M` purely by position relative to `T`).
- **C3 (order, no repeats):** within each section components appear at most once, in the fixed order `Y M D` / `H M S` — structurally enforced above.
- **C4 (anchored):** the entire string must be a `duration`; no leading/trailing/internal extra code points of any kind (including all Unicode whitespace, BOM, ZWSP).
- **F1 (fraction placement):** a `number` may carry a fraction **only if** its component is the *last* component of the whole duration (the lowest-order component present). This applies uniformly, including `week-form` (`P0.5W` valid) and date-only forms (`P1.5D` valid; `P1.5DT1H` invalid). This is ISO 8601-1's "fraction only in the lowest-order component", chosen here over the stricter "seconds only" profile — the choice is fixed, not configurable.
- **F2 (fraction shape):** ≥1 digit before and ≥1 digit after the mark; exactly one mark per number.

**Explicitly outside the grammar (hence rejected):** signs anywhere; lowercase or non-ASCII designators; non-ASCII digits; exponents (`1e5`); underscores/group separators; whitespace; `W` mixed with anything; multiple `T`; components after a fractional component.

*(Informative)* Equivalent anchored regex — **must** be compiled with ASCII-only `\d` (Python: `re.ASCII`), and needs three post-checks (≥1 group matched; if `T` matched then ≥1 of H/M/S matched; fraction only in last matched group). The DFA of §7 is normative; the regex loses error positions/codes:

```
^P(?:(\d+(?:[.,]\d+)?)W
   |(?:(\d+(?:[.,]\d+)?)Y)?(?:(\d+(?:[.,]\d+)?)M)?(?:(\d+(?:[.,]\d+)?)D)?
    (?:T(?:(\d+(?:[.,]\d+)?)H)?(?:(\d+(?:[.,]\d+)?)M)?(?:(\d+(?:[.,]\d+)?)S)?)?)$
```

## 6. Semantic mapping (lexical → value)

For each matched `number` with integer digit string `a` and optional fraction digit string `b`:

```
value = int10(a) + int10(b) / 10^len(b)        (exactly; b absent ⇒ value = int10(a))
```

`int10` interprets **ASCII digits only**, arbitrary precision (bignum). Leading zeros are legal and insignificant (`P007Y` ⇒ years = 7). No rounding ever occurs; `MAX_LEN` bounds all magnitudes, so no overflow error exists or is needed. `form` = `"week"` for `week-form`, else `"components"`. Unmatched fields = 0.

*(Informative, adversarial implementation notes)* Do **not** implement `int10` with the host's general parsers: Python `int("١٢٣")` = 123 (Unicode digits), `int(" 12\n")` = 12 (whitespace), `int("1_0")` = 10 (underscores), `float("1e5")`/`float("inf")` accept exponents/infinities. The DFA below only ever accumulates code points U+0030–U+0039, which makes those hazards unreachable.

## 7. Normative parse algorithm (single-pass DFA)

Character classes partition **all** of Unicode: `{P} {T} {Y} {M} {D} {W} {H} {S} {0-9 ASCII} {. ,} {+ - −(U+2212)} {everything else}`. Every step consumes ≥1 code point or terminates; every class has a defined transition in every state (mostly → error), giving totality (§11).

```
1. not a Unicode string           → ERR_TYPE
2. n = 0                          → ERR_EMPTY
3. n > MAX_LEN                    → ERR_TOO_LONG
4. s[0] ∈ {+,-,−}                 → ERR_SIGN(0)
   s[0] ≠ 'P'                     → ERR_MISSING_P(0)     # incl. lowercase 'p': case-sensitive
5. i=1; section=DATE; last_rank=0; count=0; count_at_T=⊥; frac_seen=false; week=false; fields=0
   ranks: Y=1, M(date)=2, D=3 | H=5, M(time)=6, S=7
6. while i < n:
     c = s[i]
     c == 'T':
        section==TIME             → ERR_UNEXPECTED_CHAR(i)      # second T
        frac_seen                 → ERR_FRACTION_NOT_LAST(i)
        section=TIME; count_at_T=count; i++; continue
     c ∈ ASCII digits:
        frac_seen                 → ERR_FRACTION_NOT_LAST(i)
        scan a = 1*DIGIT (advance i)
        if s[i] ∈ {., ,}: j=i; i++; scan b = *DIGIT
             b empty              → ERR_FRACTION_MALFORMED(j)
             frac=true
        else frac=false
        i == n                    → ERR_MISSING_DESIGNATOR(n)   # e.g. "P1", "PT1.5"
        d = s[i]
        d ∈ {., ,}                → ERR_FRACTION_MALFORMED(i)   # "PT1.2.3S"
        d ∈ {+,-,−}               → ERR_SIGN(i)
        d == 'W':
             section==TIME        → ERR_MISPLACED_DESIGNATOR(i) # "PT1W"
             count > 0            → ERR_WEEK_MIXED(i)           # "P1Y1W"
             weeks=value(a,b); week=true; i++
             i == n               → ACCEPT (week form)
             s[i] ∈ digits∪{T,Y,M,D,W,H,S} → ERR_WEEK_MIXED(i)  # "P1W2D","P1WT1H","P1W1W"
             else                 → ERR_UNEXPECTED_CHAR(i)      # "P1Wx"
        d ∈ {H,S} ∧ section==DATE → ERR_MISPLACED_DESIGNATOR(i) # "P1H","P1S": T required
        d ∈ {Y,D} ∧ section==TIME → ERR_MISPLACED_DESIGNATOR(i) # "PT1Y","PT1D"
        d ∉ section's designators → ERR_MISSING_DESIGNATOR(i)   # "P1y","PT1e5S","P1_0D"
        rank(d,section) ≤ last_rank → ERR_ORDER(i)              # repeats & inversions
        field(d)=value(a,b); last_rank=rank; count++; frac_seen|=frac; i++; continue
     c ∈ {Y,M,D,W,H,S}            → ERR_MISSING_DIGITS(i)       # "PD", "P1DD"
     c ∈ {., ,}                   → ERR_FRACTION_MALFORMED(i)   # "PT.5S"
     c ∈ {+,-,−}                  → ERR_SIGN(i)                 # "P-1D", "P0003-06-04…"
     otherwise                    → ERR_UNEXPECTED_CHAR(i)      # whitespace, unicode digits, '/', NUL, lowercase mid-string start-of-component, …
7. end of input:
     week                         → ACCEPT                       # (already accepted inline)
     count_at_T ≠ ⊥ ∧ count == count_at_T → ERR_TIME_EMPTY(n)    # "PT", "P1DT"
     count == 0                   → ERR_EMPTY_SPEC(n)            # "P"
     ACCEPT → Duration(fields, form = "components")
```

The overloaded `M` is resolved by `section`: rank 2 (months) before `T`, rank 6 (minutes) after — so `P1MT1M` is legal (1 month, 1 minute).

## 10. Fixed profile decisions *(summary of choices ISO leaves open)*

1. Fractions: allowed in the lowest-order present component only (not seconds-only, not any-field). Both `.` and `,`.
2. Signs: rejected everywhere (ISO 8601-1 profile; 8601-2 out of scope).
3. Week form: exclusive; never mixed, never converted to days.
4. Case-sensitive, ASCII-only designators and digits; zero Unicode leniency.
5. No whitespace tolerance, anchored whole-string match.
6. Exact arithmetic; `MAX_LEN = 4096`; no rounding, no numeric overflow condition.
7. No unit normalization; `form` recorded; absent fields = 0.

## 11. Totality argument

**Claim.** For every value `v` in the host input universe, `parse_iso8601_duration(v)` yields exactly one outcome from the closed set `{Ok(Duration)} ∪ {the 15 error codes}`; it terminates; and the outcome is unique (deterministic).

**Proof.**

1. **Coverage of the universe.** Step 1 splits all values into non-strings (→ `ERR_TYPE`) and Unicode strings. (In byte-string hosts, non-decoded bytes fall in the non-string branch by D1.) Steps 2–3 split strings by length into `n=0` (→ `ERR_EMPTY`), `n > MAX_LEN` (→ `ERR_TOO_LONG`), and `1 ≤ n ≤ MAX_LEN`, which proceed to the DFA. These cases are exhaustive and mutually exclusive.

2. **Transition totality.** The 12 character classes of §7 **partition all of Unicode** (the class "everything else" absorbs any code point not in the 11 explicit classes — including whitespace, controls, NUL, lone surrogates, all non-ASCII digits and letters). Inspection of §7 shows: in every reachable parser configuration (position in step 6 at component start; inside a number; at designator lookup; post-`W`), each of the 12 classes has exactly one specified transition — either advancing, accepting, or a specific error. Step 7 defines the outcome for end-of-input from every reachable configuration (`week` set / `T` with empty tail / zero components / valid). Hence no configuration lacks a rule.

3. **Termination.** Each loop iteration consumes at least one code point (`i` strictly increases) or exits via ACCEPT/error. The input is finite (`n ≤ MAX_LEN`), so the algorithm terminates in ≤ `n+1` steps, O(n) time, O(n) space.

4. **Uniqueness (determinism).** The character classes are disjoint (a partition), the algorithm is a single pass with no backtracking and no lookahead beyond the current code point, and the "first failing position wins" rule is inherent to the sequential structure. Therefore the transition sequence, and hence the outcome, is a *function* of the input. The auxiliary checks (`frac_seen`, `last_rank`, `count`, `section`, `week`) are deterministic functions of the consumed prefix. No two error codes can fire for the same input: at every step at most one branch matches.

5. **No undefined escapes.** The only computations besides the DFA are `int10` on digit strings drawn exclusively from U+0030–U+0039 with length ≤ `MAX_LEN` — total over that domain with arbitrary-precision integers — and the exact rational construction of §6, whose divisor `10^len(b)` is nonzero. There is no floating point, no locale, no recursion, and no host parser with wider acceptance (§6 note), so no exception outside the defined set can be raised and no resource bound can be exceeded beyond O(`MAX_LEN`).

6. **Soundness/completeness w.r.t. the grammar.** ACCEPT is reached only when the consumed string derives from `duration` in §5 with C1–C4, F1–F2 satisfied (the rank check enforces C3; `section` enforces C2; the `frac_seen` guard enforces F1; step-7 checks enforce C1/C2's non-emptiness; the loop's exhaustion of `s` enforces C4). Conversely, every string in the grammar's language drives the DFA to ACCEPT (each production step corresponds to a non-error transition). So `Ok` inputs = the grammar's language, and its complement within strings of valid type/length maps onto the 13 syntactic error codes.

By 1–5, the outcome relation is a **total function** on the entire input universe; by 6, it agrees exactly with the declared grammar. ∎

**Corollary (differential-testing invariant).** For all strings `s`: `parse` never returns `Ok` and an error for the same `s` under repeated calls, threads, or interpreter versions, because the outcome depends only on the code-point sequence and the constants of this spec (`MAX_LEN`, the class partition, the rank table).
