## Key

Unique ordering (slot1..slot6): F, A, B, C, E, D. A correct answer must give this exact ordering AND prove uniqueness (rule out alternatives), not just present one valid schedule.

## Answer

## Valid ordering

Slot 1 → F, Slot 2 → A, Slot 3 → B, Slot 4 → C, Slot 5 → E, Slot 6 → D
As a sequence: **F, A, B, C, E, D**.

## Verification of all five constraints (actual slots F=1, A=2, B=3, C=4, E=5, D=6)

1. A before C, C before E: 2 < 4 < 5. PASS.
2. B immediately after A: pos(B)=3 = pos(A)+1 = 3. PASS (genuine adjacency, not merely "after").
3. D after E: 6 > 5. PASS.
4. F before A: 1 < 2. PASS.
5. B neither first nor last: pos(B)=3, not 1 and not 6. PASS.

All five hold.

## Uniqueness — YES, this is the ONLY valid ordering (solution set size exactly 1)

Proved by a forcing argument, not by mere failure to find a second solution.

**Step 1 — Build the forced chain.** Only constraint (2) is adjacency; (1),(3),(4) are plain precedence. Composing them:
- (4): F < A
- (1): A < C < E
- (3): E < D

gives the strict 5-element chain **F < A < C < E < D**. B is not in this chain; its sole tie to the others is pos(B) = pos(A)+1, which places B *above* A.

**Step 2 — Locate A by counting who can sit below it.** Classify every other task relative to A: B, C, E, D are all above A; **F is the only task below A**. If A occupies slot a, the a−1 slots beneath it must be filled entirely by tasks that precede A — but F is the only candidate, so a−1 ≤ 1. Constraint (4) also forces at least one task (F) below A, so a−1 ≥ 1. Hence **a−1 = 1**, forcing **A = slot 2** and **F = slot 1**.

**Step 3 — Everything else is then forced.** B = A+1 = slot 3. The remaining slots {4,5,6} must hold C, E, D, and the chain C < E < D fixes them as C=4, E=5, D=6. No placement involved a free choice, so no other arrangement can satisfy all constraints. QED.

**Cross-check by exhausting A's position** (independent confirmation): a=1 fails (no slot below A for F); a=2 succeeds uniquely; a=3 fails (with B at slot 4, only {5,6} remain above A — two slots for three tasks C,E,D); a=4,5,6 fail (too few right-hand slots, or B=A+1 out of range). Only a=2 survives.

## Note on constraint (5)

Constraint (5) is **redundant / non-binding**: constraints (1)–(4) alone already force B into slot 3, which is automatically neither first nor last. Dropping (5) would not change the answer — it is satisfied but plays no role in establishing uniqueness.
