## Key

There are THREE distinct bugs: (1) sieve[1] is never set to False, so 1 is wrongly reported as prime (e.g. primes_below(5) returns [1,2,3] but should be [2,3]). (2) The outer loop 'range(2, int(n**0.5))' stops one short: it must be 'int(n**0.5)+1'. # Bug analysis of `primes_below`

I verified every claim below by actually running the code (buggy output and a brute-force cross-check of the fix).

## The three bugs

### Bug 1 — `1` is never marked non-prime (wrong result)
The code does `sieve[0] = False` but never sets `sieve[1] = False`. Since `1` starts as `True` and is never touched by the sieving loops (they start marking at `i*i` with `i >= 2`), it always leaks into the output.

- **Root cause:** index `1` is not prime but is left `True`.
- **Concrete input:** `primes_below(3)`
  - Expected: `[2]`
  - Actual: `[1, 2]`

### Bug 2 — off-by-one in the outer loop bound (wrong result)
`for i in range(2, int(n ** 0.5))` excludes `int(n**0.5)` itself because `range`'s stop is exclusive. A correct sieve must iterate `i` up to and **including** `floor(sqrt(n-1))`, i.e. `range(2, int(n**0.5) + 1)`. When the largest relevant prime `p` satisfies `p == int(n**0.5)`, that `p` is skipped, so its multiples (starting at `p*p`) are never crossed out and `p*p` survives as a false prime.

- **Root cause:** missing `+ 1` on the loop upper bound.
- **Concrete input:** `primes_below(10)`
  - `int(10**0.5) == 3`, so `range(2, 3)` yields only `i = 2`; `i = 3` is never processed, leaving `9` marked prime.
  - Expected: `[2, 3, 5, 7]`
  - Actual: `[1, 2, 3, 5, 7, 9]` (the `9` is purely from this bug; the `1` is from Bug 1)
  - Cleaner isolation: `primes_below(26)` leaks `25` (`5` is skipped because `int(26**0.5) == 5`), giving `[..., 23, 25]`.

### Bug 3 — crashes for `n <= 1` (unhandled edge case)
`sieve = [True] * n` produces an empty list when `n` is `0` or negative, then `sieve[0] = False` raises `IndexError`.

- **Root cause:** unconditional write to index `0` with no guard for `n < 1`.
- **Concrete input:** `primes_below(0)`
  - Expected: `[]`
  - Actual: `IndexError: list assignment index out of range`
  - (`n = 1` happens to return `[]` without crashing, but only by luck; `n = 0` and any negative `n` crash. `sieve[1] = False` in the fix also needs a guard so it isn't reached when `n < 2`.)

Note that Bugs 1 and 2 are *silent* correctness bugs (wrong list, no error), which is why they are the dangerous ones. Bug 3 is a loud crash.

## Corrected version

```python
def primes_below(n):
    """Return all primes strictly less than n, in increasing order (Sieve of Eratosthenes)."""
    if n <= 2:
        return []
    sieve = [True] * n
    sieve[0] = sieve[1] = False          # Fix 1: 0 and 1 are not prime
    for i in range(2, int(n ** 0.5) + 1): # Fix 2: +1 so floor(sqrt) is included
        if sieve[i]:
            for j in range(i * i, n, i):
                sieve[j] = False
    return [i for i in range(n) if sieve[i]]
    # Fix 3: the `n <= 2` guard covers n = 0, 1, 2 and negatives (no IndexError)
```
