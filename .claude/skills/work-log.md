# /work-log — 作業進捗ファイル管理

全プロジェクト共通の `docs/` 標準ファイルへの記録ルール。
ファイルパスは `.raptor-session.json` の各フィールドから取得する。

---

## 標準ファイル一覧

| フィールド名    | ファイル名                  | 記録内容                         |
|----------------|-----------------------------|----------------------------------|
| `summaryFile`  | `docs/SESSION_SUMMARY.md`   | セッション引き継ぎ（/rotate が書く） |
| `progressFile` | `docs/PROGRESS.md`          | 実装進捗・完了タスク             |
| `debugFile`    | `docs/DEBUG_LOG.md`         | デバッグ記録・根本原因・解決策   |
| `testFile`     | `docs/TEST_RESULTS.md`      | テスト実行結果・カバレッジ       |
| —              | `docs/REQUIREMENTS.md`      | 要件定義（人間が管理）           |
| —              | `docs/ROADMAP.md`           | ロードマップ（人間が管理）       |

---

## 更新タイミングと形式

### PROGRESS.md — 実装進捗

**いつ**: タスクを完了したとき、または作業フェーズが変わるとき。

```markdown
## YYYY-MM-DD HH:MM

### 完了
- [x] {タスク名} — {簡潔な説明}

### 進行中
- [ ] {タスク名} — {現在の状態}

### 次のステップ
1. {アクション}
```

### DEBUG_LOG.md — デバッグ記録

**いつ**: バグを発見・調査・修正したとき。

```markdown
## YYYY-MM-DD HH:MM — {バグの概要}

**症状**: {観察された動作}
**根本原因**: {特定した原因}
**修正**: {変更したファイル・行}
**確認**: {再現しなくなったことの確認方法}
```

### TEST_RESULTS.md — テスト結果

**いつ**: テストスイートを実行したとき（成功・失敗どちらも記録）。

```markdown
## YYYY-MM-DD HH:MM — {テストコマンド}

**結果**: {passed N / failed N / skipped N}
**失敗したテスト**:
- {テスト名}: {失敗理由}
**備考**: {カバレッジ・注意事項}
```

---

## 実行手順

1. `.raptor-session.json` を Read ツールで読み、対応するファイルパスを取得
2. 既存ファイルがあれば Read して内容を確認（上書きではなく追記）
3. Write ツールで絶対パスを指定して更新

---

## 注意事項

- `REQUIREMENTS.md` と `ROADMAP.md` はユーザーが管理する。変更前に確認を取ること
- `.raptor-session.json` がない場合（直接 `claude` 起動時）はパスを手動で確認する
- `docs/` ディレクトリが存在しない場合は `Bash(mkdir -p docs)` で作成してから書く
