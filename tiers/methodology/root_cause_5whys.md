# 根本原因分析 — なぜを5回

> 出典: トヨタ生産方式（大野耐一）。CLAUDE.md「失敗時の振る舞い」の背骨。

## 核

問題が起きたら、表面の症状を直して終わりにせず「なぜ？」を繰り返し、
**対策を打つべき根本原因**まで遡る。症状対処は再発する。根本対処は再発を止める。

## 例（今日の失敗に適用）

- 症状: ccr のデバッグで 1 日浪費した。
- なぜ①: 存在しない問題（インジェクション/テスト/バグ）を相手にしていたから。
- なぜ②: 対象の実在を確認せず「在る」前提で動いたから。
- なぜ③: 理解・検証より先に行動（Edit/Agent）したから。
- なぜ④: 着手前に現状把握する規律（チェックリスト）が無かったから。
- なぜ⑤（根本）: 「進め方」自体が暗黙知で、毎セッション再現される仕組みが無かった。
- **対策（根本）**: work_discipline persona + methodology + feedback memory を作り、
  着手前チェックを明文化・参照可能化した。症状（今日の混乱）でなく根本（規律の不在）に打った。

## 注意（5 Whys の落とし穴）

- **一本道に絞りすぎない** — 原因は枝分かれしうる。各「なぜ」で複数候補を考える。
- **人を責める方向に行かない** — 「誰が悪い」でなく「どの仕組みが欠けていたか」へ。
  対策は人の注意力でなく**仕組み**（チェックリスト・自動化・テスト）で打つ。
- **証拠で裏取りする** — 各「なぜ」の答えを推測でなく事実（ログ・diff・再現）で確かめる。
  さもないと 5 Whys 自体が捏造の連鎖になる。
