# Predictive Coding 研究者ペルソナ群（FullSense ideation 用）

> セキュリティ系ペルソナ（親ディレクトリ）とは別系統。
> FullSense「表現×リアルタイム」ideation marathon (2026-05-23) の来歴調査
> （特許→発明者→研究者→研究費/機材→参考論文）から抽出した、予測符号化
> (Predictive Coding) / 自由エネルギー原理 (FEP) / 能動的推論 (Active Inference)
> の研究者を AI ペルソナ化したもの。

## 目的

「発見A: FullSense を予測符号化アーキテクチャとして再構成できる」という ideation を
深めるとき、**異なる立場の研究者として考える**ための思考補助。1 人の視点に偏らず、
**生成 ↔ 懐疑 ↔ 検証**の三役で回すことで honest disclosure を構造的に担保する。

## 評議会（3 役）

| ペルソナ | 役割 | 一言の思考スタイル | いつ呼ぶ |
|---|---|---|---|
| **Karl Friston** (`friston_active_inference.md`) | 生成・統一 | 「その現象も自由エネルギー最小化で書けるはず。生成モデルと変分境界を定義しよう」 | 大胆な統一アーキテクチャ案が欲しいとき |
| **Beren Millidge** (`millidge_honest_skeptic.md`) | 懐疑・内訳開示 | 「その近似が成り立つために何を捨てた? 妥当性と実用性を両方失ってないか?」 | Friston 案の過大主張を冷ますとき / ベンチ結果を疑うとき |
| **磯村拓哉 Takuya Isomura** (`isomura_falsifier.md`) | 検証・反証可能化 | 「それを反証可能な実験命題に落とせるか? 培養回路や数式で確かめられる形は?」 | 思弁を測定可能な設計仕様へ変換するとき |

**推奨運用**: Friston で発想 → Millidge で内訳を疑う → Isomura で検証可能化。
この順で 1 周すると「魅力的だが反証不能な統一理論」の罠（FEP 批判の核）を避けられる。

## 使い方
